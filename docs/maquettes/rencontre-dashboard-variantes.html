Tableau de bord d'une rencontre — 3 variantes

Aujourd'hui l'écran empile phase, compteurs, liens, statistiques, structure éditable (14 voies), prêts et équipes : ~4 000 px de haut sur bureau. Trois façons de répartir.

A · Onglets dans la page

  • Un clic pour passer d'un domaine à l'autre
  • Vue d'ensemble = actions + alertes
  • Phase toujours visible en tête
  • Charge encore toutes les données à chaque action
  • Panneaux longs (structure) restent longs
Impact code : 1 route, onglet dans ?onglet=, panneaux existants réutilisés tels quels. Le plus léger.

B · Hub + sous-pages

  • Synthèse lisible d'un coup d'œil
  • Chaque page ne charge que ses données (moins de requêtes, cf. latence)
  • Cohérent avec /resultats, /classement…
  • URL partageable par domaine
  • Un aller-retour hub ↔ page
  • Plus de routes à écrire et tester
Impact code : 4 nouvelles routes (structure, equipes, prets, statistiques), loaders scindés, hub en comptages. Le plus structurant.

C · Guidé par la phase

  • Checklist « Prêt pour le jour J ? »
  • Seule la section utile est ouverte
  • Filtre « à compléter » sur les voies
  • Règles d'ouverture par phase à spécifier
  • Toujours tout chargé en une page
Impact code : 1 route, sections en <details>, checklist calculée dans le domaine (testable Vitest). Intermédiaire.
